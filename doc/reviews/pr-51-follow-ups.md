# PR #51 非阻塞后续项

本文仅记录 PR #51 审查中低于 P2 的问题。这些问题不单独阻塞合并，适合在阻塞项修复并合并后另行处理。

## P3：取消标记可能长期保留

- 位置：`src-tauri/src/ai/chat_runs.rs` 中的 `ChatRunRegistry::cancel`。
- 现象：取消一个未注册、已结束或已取消的 `run_id` 时，注册表会保留 `Cancelled` 标记。若之后没有同一 `run_id` 的注册操作消费该标记，它不会被清理。
- 影响：长时间运行且频繁命中这类取消时，进程内的哈希表会缓慢增长。正常交互使用唯一运行 ID，因此短期影响较小。
- 建议：给取消标记增加有界容量或过期清理，同时保留“先取消、后注册”竞态保护，并添加清理策略测试。

## P3：媒体类型匹配对大小写过严

- 位置：`src-tauri/src/ai/safe_media_fetch.rs` 中的 `collect_body`。
- 现象：代码用区分大小写的 `starts_with("image/")` 或 `starts_with("audio/")` 校验 `Content-Type`。HTTP 媒体类型的 type/subtype 语义不区分大小写，因此合法但少见的 `Image/PNG` 会被拒绝。
- 影响：部分非标准化供应商返回大小写混合的媒体类型时，生成结果会被误报为类型不受支持；安全边界本身没有被放宽。
- 建议：解析媒体类型后按 ASCII 小写比较，并增加大小写混合的响应测试。

## P3：回滚快照清理警告可能无法持久化

- 位置：`src-tauri/src/pipeline/run_driver.rs` 中清理旧回滚快照后的 warning 保存。
- 现象：清理失败会把诊断写入当前 Step 尝试记录，并以 best-effort 方式再次保存 Run 状态；如果磁盘此时仍不可写，这条 warning 不会留在重载后的历史中。
- 影响：可能丢失一次非关键清理诊断，但不会发出虚假的完成、失败或超时终态；待清理快照本身仍保留在磁盘上。
- 建议：后续将清理诊断放入独立、可重试的维护记录，或在下一次成功保存 Run 时重新附加未持久化的 warning。
